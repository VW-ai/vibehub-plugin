# Harness Chat v1 review

Status: rejected visual baseline retained as negative evidence. The owner
rejected the complete custom-shell style on 2026-08-17 and redirected the
product to begin from the current Codex interaction baseline. Do not polish or
extend this visual system; retain only its interaction findings.

## Taste signals applied

- The application shell recedes so current work receives attention.
- The first frame is a normal Agent Chat, never a Dashboard.
- Workspace, Session, and model identity stay stable without becoming panels.
- Branch, Context, and Ticket actions happen beside the conversation that owns
  them.
- Execution is absent before Start. Trusted Run activity appears only after
  explicit execution and crosses the page only for attention.
- Compact hierarchy replaces cards, marketing typography, glow, grids, and
  decorative AI imagery.

## Exact walkthrough

1. Read and scroll the normal Main conversation.
2. Hover an assistant answer section and choose `Fork from here`.
3. Open `Branches`, enter a branch, or compare the two example forks.
4. Use `Bring back to Main`; confirm that it appends a source-linked turn rather
   than merging or deleting either branch.
5. Open `Context`, inspect the Workspace-scoped references, and use the selected
   packet. Confirm that the attachment is visible at the composer and removable.
6. Open `Make task`, judge the inline readiness preview, and choose
   `Create & start`.
7. Confirm that a narrow trusted Run strip appears only after execution starts,
   while Chat and its composer remain fully available.
8. Open the Run, preview an attention request, and resolve it at the owning
   verification step.

The global command layer is available from the application bar or `Command K`.
It routes human UI actions directly and does not manufacture model turns.
