# Harness visual direction review

Status: rejected visual study retained only as negative evidence. On 2026-08-17
the owner rejected all three directions as visually dated and "土土的". Do not
iterate, combine, or use them as the baseline for the whole-application
prototype.

The replacement gate is a taste-calibration board made from real product
screenshots. It asks the owner to identify acceptable whole-product and local
interaction qualities before VibeHub produces another original interface.

## How to review

Open the local direction study and compare the same scenario in all three
directions. Review `First frame`, `Chat at work`, and `Active runs` before
opening one direction full-screen. The Notes control explains the intent and
risk behind each direction.

Judge five questions:

1. Where does attention land before the user knows the navigation?
2. Does normal Chat remain calm and unconstrained?
3. Does trusted execution feel present without becoming a wall of logs?
4. Can Branch, Context, Ticket, Run, attention, and Evidence become one
   coherent visual language?
5. Would the environment remain pleasant when left open all day?

The study intentionally does not ask the owner to accept the full Ticket loop,
responsive product shell, or DSH extension mapping. Those remain acceptance
boundaries for the subsequent whole-application prototype.

## Direction 01: Ambient OS

The current intention owns the field. Navigation recedes to the edge. Trusted
work appears as persistent ambient signals and becomes explicit when it needs
attention. The full branch topology is a temporary zoom-out state rather than
the default surface.

- Reference mix: Dia's low-chrome environment, Raycast's command velocity,
  and Warp's cross-application execution presence.
- Strength: the most differentiated and personal product identity.
- Risk: restraint may become vague unless Ticket, attention, and Evidence have
  crisp object surfaces.

## Direction 02: Spatial Cockpit

Conversations, Tickets, Context, and Runs occupy one navigable field. Chat is a
focused panel inside that field. Explicit forks create visible paths; semantic
similarity never creates graph edges.

- Reference mix: Msty Branch Explorer, conversation-graph research, and local
  Agent canvases.
- Strength: the clearest expression of branch, compare, and parallel work.
- Risk: canvas mechanics may become the product and impose navigation cost on
  ordinary Chat.

## Direction 03: Kinetic Command

A compact work queue makes readiness, current activity, and human attention
legible in one scan. Branches use tabs and lineage. Runs use precise event
rows, progress steps, and a persistent status lane.

- Reference mix: Linear's hierarchy and density, Warp/Oz run supervision, and
  Raycast's action model.
- Strength: the fastest to understand and the lowest interaction risk.
- Risk: it may become a polished operations dashboard instead of a new
  personal task-and-thought environment.
